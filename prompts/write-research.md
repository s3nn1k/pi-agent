# Итоговый research/spec-документ

> Канон содержания - скилл doc-canons (документ = готовая спецификация, не лог сессии).
> Тест-кейсы фичи - отдельным файлом после финализации спеки (отдельная команда).

## Запуск и режим соавторства

Вход - тема или путь к спеке/заметкам (аргумент команды). Ты - соавтор: предлагаешь
структуру, пишешь разделы, каждый раунд сверяешься с каноном документа (скилл doc-canons),
незакрытые вопросы отдаёшь человеку.

### Где живёт документ

По умолчанию - личный vault. Work-исследовательские документы -
`~/vaults/work/researches/`. Если там уже есть файл по теме (или близкий) - показать
пользователю и редактировать существующий, дубликат не плодить. Если vault'а нет - в
репозитории (`docs/`). В одном месте - ровно один канонический файл.

### Фаза 0 - факты (в черновик, не в документ)

Собери основу: прочитай релевантный код/схему/существующий текст. Это процесс - в готовый
документ он не попадает.

### Фаза 1 - скелет (согласуется с человеком)

Предложить структуру: **Термины** (определение каждой величины/символа upfront) ->
**Шаги/Логика** по разделам -> плейсхолдеры **Вопрос/Ответ** где нет данных. Дождаться
"ок".

### Фаза 2 - пишем по разделам (цикл)

По одному разделу за проход: черновик нейтральным языком от третьего лица -> самопроверка
по канону документа (скилл doc-canons) -> показать человеку, правки внести.

### Фаза 3 - финальный прогон

Прочитать документ целиком и вычистить: следы расследования, лишнюю прозу, эмодзи,
посторонние окружения (beta/внешний gateway - если документ про прод). Проверить, что нет
"уточнить" без плейсхолдера. Показать финал + список мест, где нужен ввод человека. После
финализации тест-кейсы фичи выноси отдельным файлом отдельной командой; передай ей путь к
спеке.
