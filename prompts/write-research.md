Пиши итоговый документ. Тема/путь: **$@**. Если пусто - спроси тему и место, где живёт
документ; если в контексте нет плана/черновика - спроси его, не выдумывай.

# Итоговый research/spec-документ

> Канон содержания - скилл doc-canons (документ = готовая спецификация, не лог сессии).
> Уточнение требований - скилл spec-clarification (вопросы в чат, не в документ).
> Тест-кейсы фичи - отдельным файлом после финализации спеки (отдельная команда).

## Режим: один проход

Вход - план в контексте сессии (обсуждение, интервью, черновик, заметки). Документ
выписывается целиком сразу в финальном виде: без согласования скелета, без черновиков по
разделам, без ожидания "ок". Показ - готовый документ.

Незакрытые решения закрываются до написания раундом вопросов в чате (скилл
spec-clarification); документ несёт только согласованные решения. Ответа нет - фрагмент не
пишется, вопрос остаётся в чате и перечисляется в сообщении сдачи.

### Где живёт документ

По умолчанию - личный vault. Work-исследовательские документы -
`~/vaults/work/researches/`. Если там уже есть файл по теме (или близкий) - показать
пользователю и редактировать существующий, дубликат не плодить. Если vault'а нет - в
репозитории (`docs/`). В одном месте - ровно один канонический файл.

## Гейты

- Перед написанием: релевантный код/схема прочитаны - факты, не процесс.
- После: самопроверка по реестру doc-canons целиком - следы расследования, повторы,
  компактность; `TODO:`/"Вопрос / Ответ" в тексте нет.
- Сдача: показать документ + список мест, где сделан выбор из неоднозначных (если был).
  После финализации тест-кейсы - отдельной командой; передай ей путь к спеке.
