# Каноны доменных артефактов

## Применимость

Канон вида повторяемого доменного артефакта; один вид = один reference, правила вида живут
в нём целиком:

- **research/spec-документ** - итоговая спецификация (результат, не лог расследования) -
  `references/research-doc.md`;
- **файл функциональных тест-кейсов** - спецификация покрытия фичи, `<filename>_tests.md`
  рядом со спекой - `references/test-cases.md`;
- **сообщение в канал product** - анонс фичи по тех. проработке -
  `references/product-message.md`;
- **разбор инцидента** - postmortem-отчёт: что произошло, почему, влияние, action items -
  `references/incident-report.md`.

Границы соседей (дубль - отошли к соседу):

- поверхность текста (ASCII-пунктуация, переносы, таблицы) - не здесь;
- конфигурация харнеса (скиллы/промпты/агенты) - не здесь;
- исполнение integration-тестов - не здесь, здесь формат кейс-файла.

## Эталон

Скелеты всех видов - модель достраивает форму; полный скелет - в reference вида:

```text
research/spec-документ            файл тест-кейсов
# <Тема>                          ### <область>
- [[#Раздел]]                     - happy.<суть>
## Термины (каждая величина)      Given: <предусловия>
## Шаги / Логика (по разделам)    When: <вызов интерфейса>
## Итерации и задачи (R-14)       Then: <наблюдаемый исход>
                                  (нет аналога - колонка тест-кейсов)

сообщение в канал                разбор инцидента
🔶<Фича>                          # <дата> <Имя>
<суть для читателя>              ## Основная информация
🔷<Раздел> / 🔹-пункты           ## Разбор / Таймлайн / Выводы
                                  ## Action Items (таблица)
```

## Реестр правил

- R-1 Правила вида артефакта - целиком в его reference (один вид = один реестр); SKILL.md
  их не дублирует.

## Каталог

| Ситуация                              | Reference                       |
| ------------------------------------- | ------------------------------- |
| Пишу/правлю research/spec-документ    | `references/research-doc.md`    |
| Пишу/правлю файл тест-кейсов          | `references/test-cases.md`      |
| Пишу/правлю сообщение в канал product | `references/product-message.md` |
| Пишу/правлю разбор инцидента          | `references/incident-report.md` |
| Поверхность текста любого из них      | не здесь                        |
| Исполнение тестов по кейсам           | не здесь                        |

## Где глубже

- `references/research-doc.md` - принципы содержания research/spec-документа.
- `references/test-cases.md` - формат кейса, id-конвенция, именование файла, каталог
  охвата.
- `references/product-message.md` - каркас и содержание сообщения в канал product.
- `references/incident-report.md` - каркас разбора инцидента: шапка, таймлайн, action
  items.
