# Канон сообщения в канал product

Сообщение - анонс фичи для читателей канала (продукт, биздев, поддержка): что изменилось
для пользователей. Источник - тех. проработка. Здесь - каркас и содержание; формулировки
предложений - канон стиля прозы; маршрут (preflight, показ, правки) - у вызывающей
команды, не здесь.

## Эталон

Каркас; разделы опциональны - по содержанию фичи:

```
🔶<Название фичи>

<1-2 предложения: что появилось и для кого>

🔷Преимущества
- <пункт>
- <пункт>

🔷Принцип работы
1. <шаг>

<Сопутствующие улучшения, если есть>
```

Компактная форма - малые фичи (одно изменение без флоу):

```
🔶<Название>

🔹 <что появилось>
🔹 <где настраивается / как считается>
```

## Реестр правил

### Каркас

- R-1 Заголовок - `🔶` + короткое название фичи; без кавычек и точки.
- R-2 Эмодзи каркаса фиксированы: заголовок `🔶`, раздел `🔷`, пункт компактной формы
  `🔹`; других эмодзи нет.
- R-3 Раздел - `🔷<Имя>` без пробела, имя по содержанию (типовые: "Преимущества", "Принцип
  работы"); внутри раздела `-` для перечислений, `1.` для шагов флоу.
- R-4 Компактная форма - без разделов, каждый факт отдельной строкой с `🔹`.

### Содержание

- R-5 Пишем для читателя канала, не для команды: что изменилось для мерчанта, трейдера,
  админа; реализация (сервисы, таблицы, флаги, миграции) в сообщение не попадает; термин
  проработки идёт под именем, знакомым читателю.
- R-6 Один пункт - один факт, телеграфом; клише и реклама ("стало удобнее и надёжнее") -
  вон.
- R-7 Числа и условия (лимиты, интервалы) - из проработки дословно; без округлений и
  "примерно".
- R-8 К посту приложатся скрины - место помечается `(скрин N)` в конце связанного пункта,
  нумерация сквозная; скрины прикладывает человек.
- R-9 Объём следует фактам: флоу целиком, не резать; ориентир ~35 строк, длиннее - первыми
  резать сопутствующие улучшения и детали настроек.
