# Канон промпт-команды

Файл: `prompts/<name>.md`. Имя файла без `.md` = команда (`/name`). Discovery
non-recursive. Тело разворачивается в user-сообщение = ход агента.

```markdown
---
description: <что делает; для autocomplete; императив желателен>
argument-hint: "<обязательные> [необязательные]" # опц.
---

<императивный зачин: "Приведи/Настрой/Запуши...". Аргумент: **$@**.>
<жанр тела - развилка ниже>
```

Правила:

- Промпт = вызываемая команда, не авто-грузимый скилл. Различие - по механизму (скилл
  авто-грузится по description, промпт вызван командой); размещение нового - по
  переиспользуемости (R-19). Жанры "что куда":

  | Строка тела                                | Дом                            |
  | ------------------------------------------ | ------------------------------ |
  | доступ к внешней системе (API, токены,     | скилл-дом системы              |
  | quirks)                                    |                                |
  | справочник/digest API, таблицы ключей      | скилл + references (R-7, R-12) |
  | канон вида артефакта (принципы документа,  | скилл; промпт-обёртка - вход   |
  | формат кейсов)                             |                                |
  | фазы, делегирование, апрув-стопы, контракт | промпт                         |
  | сдачи, константы задачи                    |                                |

- Жанр тела развилкой:
  - **производит артефакт** -> спецификация: Эталон + Каталог; LLM достраивает форму,
    пошаговый рецепт не нужен. Эталон в теле - только для уникального артефакта этого
    вызова; канон повторяемого вида (принципы research/spec-документа, формат тест-кейсов)
    живёт в скилле (R-19), промпт ссылается на скилл по имени;
  - **оркестрирует фазы/делегирует** (resolve-review) -> процедурный Workflow - гейты
    (делегирование, корректность); пошаговость уместна. Композиция универсальна: домены не
    хардкодятся - каноны фаз разрешаются на вызове (аргумент > контекст проекта/диффа из
    каталога скиллов > спроси), команды и детали домена живут в канонах, не в теле.
    Эталон - `prompts/resolve-review.md`.
  - **обёртка над скиллом-маршрутом** -> вход задачи + указатель на маршрут; знание живёт
    в скилле, не в теле. Два вида:
    - библиотека workflow (паттерны оркестрации): вход + имя паттерна. Эталон -
      `prompts/write-feature.md`.
    - доменный маршрут скилла: вход + скилл + reference с маршрутом фаз.
- Аргументы: `$@` (всё одной строкой), `$1`/`$2`, `${1:-default}`, `${@:N}`. Вход может
  быть пустым -> спроси, не выдумывай.
- Самодостаточность: правила этой задачи внутри промпта допустимы (one-shot: тело
  разворачивается раз за вызов и не грузится в каждый контекст); норма, нужная другой
  задаче, - скилл (R-19), промпт ссылается на скилл по имени целиком.
- НЕ: пассивная простыня без команды или справочник/механика без задачной семантики (это
  скилл, R-19); пошаговый рецепт для артефакт-жанра.
