# Канон агента (subagent)

Файл: `agents/<name>.md`. Frontmatter + тело = system-prompt агента. Project
(`​.pi/agents/`) перекрывает user; builtin-имя тоже перекрывается.

Обязательные frontmatter-поля:

| Поле             | Описание                                                                                                                                                              |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`           | lowercase `a-z/0-9/-`, <=64                                                                                                                                           |
| `description`    | когда оркестратор выбирает агента                                                                                                                                     |
| `model`          | bare id -> текущий провайдер; `"provider/id"`; `"router/<tier>"` - виртуальная модель роутера (квоты/failover на каждый запрос); без поля -> `subagents.defaultModel` |
| `tools`          | allowlist builtin; `mcp:<name>`; `./x.ts` - extension. Опущено = обычные builtin                                                                                      |
| `defaultContext` | `fresh` \| `fork`                                                                                                                                                     |

Ключевые опц.: `thinking` (`:level`), `extensions`/`subagentOnlyExtensions`,
`inheritSkills`/`skills`/`skillPath`, `inheritProjectContext`, `systemPromptMode`
(`replace` дефолт \| `append`), `output`, `defaultReads`, `completionGuard`,
`maxSubagentDepth` (Leaf: `0` - норма Leaf ниже).

fresh vs fork: `fresh` - чистый, только задача + свой промпт (дефолт для кастомных);
`fork` - ветка сессии родителя с фильтрацией (дефолт для packaged planner/worker/oracle).

Override builtin без копирования файла: `settings.json` ->
`subagents.agentOverrides.<name>` (`model`/`tools`/`skills`/`disabled`/...;
`disabled:true` - скрыть).

Правила тела:

- **Тело = только поведение, без правил.** Канон живёт в `skills:`; тело - роль +
  процедура + границы + формат вывода + указание авторитета ("единственный источник
  правил - скилл X, прочитай его перед работой"). Выжимки/хард-правила из скилла в теле -
  дубликат расходится с каноном и перекрывает его. Нормативный скилл - писатель/ревьюер
  ходит по реестру целиком, тело лишь требует этого.
- **description - широкий триггер роли:** "что агент делает" + свойства (стек, канон,
  read-only). Рецепт оркестрации ("кем звать", "после какого агента", "параллельно с кем")
  живёт в промпте-оркестраторе, не тут.
- **Одна тяжёлая ось на агент.** Типовой инстанс - ревьюер: ось канона (per-rule вердикт
  по реестру скилла) и ось надёжности (адверсал: "изменение сломано, пока не доказано
  иное"; замечание = конкретный сценарий отказа) конкурируют за внимание. Обе тяжёлые ->
  два агента параллельно, вердикты мержит оркестратор. Адверсальность - свойство роли, в
  скилл не утекает; канон-ревьюер правил не придумывает - только реестр.
- Не плодить дубль-роль: проверь builtin и соседей.

## Универсальные роли (домен != роль)

Роль не привязана к домену; доменное знание приезжает каноном (скиллом). Новый домен =
скилл в каталог + пин при запуске, **не** новый агент. Доменный агент оправдан только
уникальным контрактом (спец-формат/инструменты), не знанием.

**Агент рождается пустым:** `inheritSkills: false` и без `skills:` - ребёнок видит ровно
выданное оркестратором. Исключение - механизм роли: скилл, без которого роль не работает,
зашивается парой `skills:` + `skillPath:` (путь от `agents/`), сам скилл живёт вне
дискавери main. Тяжёлый побочный вывод механизма - аргумент за такую роль, не за скилл в
main.

Разрешение канона (первое сработавшее выигрывает):

1. **Пин:** скилл, переданный при запуске; заменяет каталог на этот запуск.
2. **Self-route:** один скилл из каталога `skills:` frontmatter по домену задачи/диффа;
   выбор объявляется в выводе (reviewer - режим-строкой первой строкой). Каталога нет
   (норма для универсальных ролей) - шаг пропускается, не подмена.
3. **Baseline:** worker - house-правила, для кодовой правки - только по явной пометке
   «доменного канона нет» в таске (базовый реестр стиля + gate до сдачи: форматтер,
   линтер, затронутые тесты; канон домена детализирует, совпадение с реестрами скиллов -
   перенос baseline, не выжимка); reviewer - дефект-ревью только по явной рамке таски.

**Стоп-ошибка делегирования:** канон подразумевается, но не передан и однозначно не
разрешается (кандидатов нет или 2+) - агент возвращает "перезапусти со скиллом X" без
вердикта; тихий даунгрейд до дефект-ревью/house-правил запрещён. Промпт-композиция
моделирует этот третий исход (немедленный стоп цикла) и дублирует имя канона текстом в
таске. Пин - свободная строка; его потеря при запуске родителю не видна.

Сопутствующие нормы:

- `skills:` frontmatter - механизм роли или каталог редкой self-route роли; норма
  универсальной роли - без списка: канон приезжает пином (name+desc в промпт, тела lazy).
- Граница домена: правки только в домене канона задачи; файл вне домена - стоп и
  эскалация, не house-правила.
- Read-only механизм: allowlist `tools: read, bash` + клауза тела "bash - только
  инспекция".
- Leaf: `maxSubagentDepth: 0` в frontmatter; клауза "не делегируй" в теле - только ролям с
  полным tools (writer).
- Контракт вывода (режим-строка, APPROVED/CHANGES_REQUESTED, HIGH/MED/LOW) потребляют
  промпты-композиции; смена формата = синкать их же.
