# Три модели содержания и их доли

Глубина к Реестру harness-authoring (весь реестр).

## Convention / target-state (~60%, ядро)

Эталон (скелет артефакта) + Реестр правил (плоский пронумерованный список всех норм) +
опц. Каталог конструкций (навигация "ситуация -> паттерн"). LLM блестяще достраивает
паттерн под задачу - покажи форму, она её допишет.

## Workflow / гейты (~20%)

Запуск/тулзы (`make lint`, `scaffold.sh`, `web.mjs`) и точки корректности ("тест падает
без реализации", "нет моков"). Не хребет для craft (код/архитектура): LLM - не конечный
автомат, на шаге 8 дрейфует. Уместны в оркестрации (фазы, делегирование).

## Reference / справочник (0% в основном файле, 100% в references/)

Сигнатуры, исчерпывающие примеры, коды ошибок.

## Жанровая зависимость долей

- Tool-скиллы (поиск/браузинг) и скаффолдеры (генерация каркаса) - workflow-тяжелее, живут
  без реестра.
- Craft/нормативные (канон кода, канон тестов) - convention-тяжёлые, реестр обязателен.

Модель из 4 вопросов (Зачем/Как/Нормы/Глубина) универсальна: любой жанр, любой вид
артефакта - скилл, промпт, агент, таск.
