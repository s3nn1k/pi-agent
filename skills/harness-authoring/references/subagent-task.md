# Канон таска субагенту

Таск = единственный вход дочернего агента (у fresh нет истории сессии). Оркестратор пишет
таск по формуле: самодостаточный контекст + границы + формат возврата. Скелет:

```text
<что сделать: цель одним абзацем; чей канон читать - скиллы по имени>

ГЕЙТЫ: свежесть базы, чистота дерева (или явное "дерево грязное - вот почему");
стоп-условия (аномалия -> стоп и вопрос, не импровизация)

ЧТО СДЕЛАТЬ: нумерованные пункты; per-repo значения явно; что сохранить как есть

ВАЛИДАЦИЯ: команды, обязанные пройти (lint/template/тесты)

ГРАНИЦЫ: что НЕ трогать (файлы/каталоги); сколько коммитов; пуш/без пуша

ВЕРНИ: формат отчёта (файлы, результаты, sha) - оркестратору, не человеку
```

Правила:

- Самодостаточность: cwd, скиллы (`skill: [...]` или "прочитай скилл X по пути"),
  канон-файлы по путям, per-repo значения - всё в таске; fresh-агент не видит сессию
  родителя и не должен ничего угадывать.
- Один пишущий агент на cwd; параллельные писатели - worktree, иначе последовательные
  runs.
- Канон передаётся скиллом по имени, не пересказом в таске; пути к canon-файлам можно.
- Стоп-условия обязательны: что считать аномалией (чужие коммиты, грязное дерево, конфликт
  rebase, упавшая валидация) -> стоп и вопрос супервизору, не обход.
- Формат возврата фиксирует отчёт: оркестратор синтезирует и сдаёт человеку; дочерний
  агент не пишет человеку напрямую.
- Вопросы - через supervisor-канал (intercom), не молчанием и не выдумкой.
