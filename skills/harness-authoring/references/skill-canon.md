# Канон скилла

Формат: каталог с `SKILL.md` (+ опц. `references/`, `scripts/`, `assets/`). Frontmatter -
только `name` + `description` + тело; иных полей нет.

Скелет SKILL.md - 4 вопроса по порядку:

```markdown
---
name: <lowercase a-z0-9-, <=64 - механика платформы, не норма>
description: <повелительное: "используй, когда..." + краткий охват + "НЕ для..."; <=1024 - механика платформы; триггер загрузки, не конспект правил>
---

# <Заголовок>

## Применимость # Q1 ЗАЧЕМ/КОГДА: какие задачи покрывает (триггер загрузки) + границы

## Эталон # Q2 КАК ДОЛЖНО БЫТЬ: скелет целевого артефакта (дерево папок / code-скелет), не проза - модель достраивает форму

## Реестр правил # нормативные скиллы: ВСЕ требования/запреты/краевые - единый нумерованный список R-1..R-N по смысловым блокам (`###`, нумерация сквозная); ID стабильны; гейт-проверяемые - отдельным блоком в конце; absence-правила с клаузой "Проверка:" (полная норма - R-6)

## Каталог конструкций # опц.: навигация по неоднородному выбору "ситуация -> паттерн/R-ID" (таблица); НЕ отдельный источник правил

## Workflow # ~20% - гейты, не шаги: запуск/тулзы И точки корректности; НЕ хребет для craft

## Где глубже # references = справочник (сигнатуры/примеры/WHY) БЕЗ формулировок правил, со ссылками на R-ID; 0% канона в SKILL
```

Специфика:

- Скилл авто-грузится по description (progressive disclosure: name+desc в промпте, тело по
  read). Ручной вызов - `/skill:<name>` (аргументы добавляются к телу).
- Tool-скиллы и скаффолдеры (script+skill) - workflow-тяжелее, живут без реестра;
  craft/нормативные - convention-тяжёлые, реестр обязателен.
- Пример описания формы description (триггер, не конспект): "Используй, когда пишешь или
  ревьюишь integration-тесты: флоу через HTTP-ручки запущенного сервиса. НЕ для
  unit-тестов - канон кода".
