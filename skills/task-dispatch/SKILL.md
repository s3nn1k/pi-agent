# Диспетчер задач: гейт, класс, исполнитель

## Применимость

Первая проверка любой задачи изменения, из любого входа (команда, чат, замечание MR) - до
первой правки и первого запуска субагента. Результат - объявленный класс; класс задаёт
исполнителя, маршрут и бюджет.

## Эталон

Гейт - "новая логика работы?": меняется ли поведение системы или артефакта для
потребителя.

```text
новой логики нет -> XS: main сам, 0 субагентов; канон вида + гейт репо
новая логика     -> класс >= S: конвейер с ревьюером и доменным каноном
                    (код - code-style, документ - канон вида);
                    S/M/L/X дальше по риску x размеру
```

Классы (прогноз диффа, не ключевые слова домена):

- **XS** - правка без новой логики и с известным эффектом: значения конфига, статичный
  контент, поверхность текста, одноразовый прототип/спайк, точечный артефакт без канона.
- **S** - малая правка с новой логикой: <= 2 файлов, локальный эффект, без контракта
  наружу, миграций, правок денег/доступа и транзитивного эффекта на потребителей
  (deps-бамп - не S). Типовой инстанс: точечный фикс, мелкая логика.
- **M** - средняя: один домен, новая логика или 3+ файлов; контракт наружу только
  аддитивный (новое поле/эндпоинт без смены поведения существующих потребителей).
- **L** - риск: смена поведения существующих потребителей, необратимые данные (миграция),
  инварианты денег/доступа, кросс-доменные изменения; фича со спекой.
- **X** - вне конвейера: ресёрч, миграция инструментария, эксперимент; маршрут свободный.

Артефакты фичи (doc/plan/tests) обязательны для L; M - план в таске; S и XS - задача
текстом. Доменный документ классифицируется по риску замысла, не по объёму текста.

## Реестр правил

- R-1 Гейт "новая логика работы" - первая ось классификации: логики нет - XS независимо от
  числа файлов; есть - минимум S с ревьюером и доменным каноном. Эффект правки
  неизвестен - не XS.
- R-2 XS исполняет main сам: без субагентов и циклов; канон вида main держит сам (`.md` -
  md-text), код - гейт репо (`make lint`); ревьюер/adversarial - нет. Всплыла новая логика
  в процессе - стоп и переклассификация этим гейтом.
- R-3 Класс не легче тяжести канонной валидации домена: канон требует живого прогона или
  мутационных доказательств - минимум M даже при форме XS/S.
- R-4 Спорное XS|S -> S; S|M -> M; M|L -> вопрос человеку; человек переклассифицирует
  словом.
- R-5 Класс объявляется первой строкой разметки/сдачи. Проверка: у каждой запущенной
  задачи объявлен класс.
- R-6 Класс >= S - маршруты, роли и бюджеты: скилл subagent-orchestration; XS его не
  грузит.
