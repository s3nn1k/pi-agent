# Визуальная подача: минимальный вид вместо прозы

## Применимость

Подача структурной темы человеку в чате: контракты срезов, схемы конвейеров, разборы "что
где живёт / что изменится" - по умолчанию при обсуждении, без просьбы. MR-тела и документы
остаются компактной прозой своих канонов.

## Эталон

Вид = наименьшая структура, несущая точку; имена реальные, из кода/темы:

```text
submitOrder
  createSession
    persistPrompt
  notifyMerchant
```

```diff
 src/orders/
+  split.go        # вынос группировки позиций
 src/transport/
-  client.go
+  http/client.go
+  http/stream.go
```

## Реестр правил

- R-1 Минимальный вид: наименьшая форма, которая делает точку ясной; узлы, поля и шаги вне
  точки - убрать.
- R-2 Вид по вопросу: логика -> псевдокод; порядок вызовов -> call-tree; раскладка или
  рефакторинг -> мелкое дерево файлов с однострочными ролями; структура UI -> дерево
  компонентов с границами модулей; изменение существующей формы -> diff-шeйп; новое
  целиком -> полный блок; взаимодействие участников -> mermaid (только если среда
  рендерит); плотное сравнение или UI-макет -> HTML-артефакт.
- R-3 Реальные имена: пути, символы, состояния, лейблы - из кода или темы; placeholder
  ("Component", "foo") запрещён.
- R-4 diff-шeйп повторяет форму оригинала: изменение дерева - деревом, call-tree -
  call-tree'ем, логика состояний - псевдокодом; полный блок вместо диффа - когда материал
  новый целиком или дифф прячет владение и порядок.
- R-5 HTML-артефакт: один файл - одна точка; реальные данные и цвета продукта; после
  записи открыть (`open <path>/show-me-<slug>.html`); не применять к тому, что влезает в
  текстовый вид.
- R-6 Место применения - чат; MR-тела - компактные пункты гит-канона, сюда не расширяются.
- R-7 Вид стоит рядом с 1-2 строками текста, которые он поддерживает; проза,
  пересказывающая вид, - вон. Все виды сразу - не использовать.

## Каталог

| Вопрос                                 | Вид                     |
| -------------------------------------- | ----------------------- |
| Как работает логика/ветвление          | псевдокод               |
| Кто кого зовёт / в каком порядке       | call-tree               |
| Где что лежит / план раскладки         | дерево файлов с ролями  |
| Что изменится в существующей структуре | diff-шeйп той же формы  |
| Как взаимодействуют участники          | mermaid (если рендерит) |
| Сравнение состояний/UI, плотная тема   | HTML-артефакт           |
