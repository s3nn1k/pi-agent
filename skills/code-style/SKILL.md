# Стиль кода: универсальный реестр

Применяется к любому коду в любом репо. Доменные скиллы расширяют дельтами, не дублируют;
расхождение домена с реестром - баг канона, фиксить канон, а не отступать молча.

## Эталон

Пример на основном стеке; нормы - для любого языка. Имя и структура говорят сами,
комментариев нет, ошибка обрабатывается громко.

```go
func (r *repository) UpsertPayment(ctx context.Context, p models.Payment) error {
	if _, err := r.db.Exec(ctx, upsertQuery, pgx.NamedArgs{"id": p.ID}); err != nil {
		return fmt.Errorf("UpsertPayment: %w", err)
	}
	return nil
}
```

## Реестр правил

- **R-1** Самодокументирующийся код: имена (переменных/функций/типов) и структура несут
  смысл; функция делает ровно то, что в названии. Смысл, который можно убрать в имя/тип
  или структуру, - туда, не в комментарий. Имена без обрезок-сокращений (enc, cnt, mgr,
  req) - полное слово; тип-агрегат не называется именем своего поля (OperatorKey.Key -
  ошибка имени: OperatorAccount.Key).
- **R-2** Комментарии не пишем вообще; исключение одно - TODO-поручение с условием снятия:
  что сделать + когда снять
  (`// TODO(#MM-123): убрать компенсацию, когда провайдер закроет дубль вебхука`; "TODO:
  переписать" - не поручение). Всё остальное - шум, удалять, не переписывать:
  rationale/"почему", факты о внешних системах и контракты (их несут код, имена, тесты),
  док-комменты и package-doc, ярлыки секций и навигация "где что менять", пояснение
  значения (требующее пояснения значение - имя константы), пересказ имени/шагов, "теперь
  так / раньше иначе", ссылки на внешние документы, закомментированные блоки. TODO - на
  русском. Легаси-окружение и "в стиле файла" не оправдание: правило - для добавленных
  строк диффа. Проверка: перечислить комментарии диффа -> каждый - TODO-поручение;
  прочие - удалить.
- **R-3** Мёртвого кода нет: закомментированные куски, неиспользуемые импорты/переменные,
  недостижимые ветки. Проверка: unused-сигналы линтера + закомментированный код в
  добавленных строках диффа.
- **R-4** Ошибки - громко: не глотать молча; обработка явная, сообщение осмысленное.
  Упрощение и перенос кода сохраняют валидацию на границах доверия, проверки доступа и
  гарантии сохранности данных. Проверка: перечислить удалённые/перенесённые проверки и
  обработчики ошибок в диффе -> для каждого показать, где сохранена его гарантия.
- **R-5** Переиспользование, не переписывание: перед новым хелпером - поиск по репо и
  скиллам; похожее схлопываем, если не ломает смысл.
- **R-6** Минимум зависимостей: stdlib и платформенное - прежде новых пакетов; уже
  используемые/vendored - прежде реимплементации.
- **R-7** Без лишней сложности: если синхронно/прямо достаточно - не плодить асинхронные
  обвязки и преждевременную абстракцию. Минимальное полное изменение, не минимум строк:
  затронутые вызывающие места, тесты, фикстуры, конфиги и экспорты согласованы.
  Незапрошенные возможности и код "на будущее" не добавляем. Проверка: перечислить новые
  абстракции, параметры и ветки поведения в диффе -> каждое необходимо для задачи или
  совместимости.
- **R-8** Один файл - одна смысловая роль; при росте дробим по смыслу, не копим.
- **R-9** Gate до сдачи: форматтер языка + линтер + затронутые тесты; команды - канон репо
  (Makefile/CI), типично `make lint` + тесты пакета. Красный gate - не сданная работа.
- **R-10** README и доки при коде (scripts/, tools/) - компактные, только суть: как
  запустить + по одной строке на сущность (что делает -> результат) + порядок. Ориентир до
  ~40 строк; внутренности не пересказывать - их разберут по коду. Проверка: длина файла и
  отсутствие разделов, пересказывающих реализацию, процесс или конфигурацию за пределами
  "как запустить".
- **R-11** Обёртка 1:1 без добавления поведения - не создаём: зовём цель напрямую,
  доменизацию ошибки делает вызывающий (`fmt.Errorf("%w: %w", ...)`). Типовой инстанс -
  пере-экспорт сторонней библиотеки (функция A возвращает lib.B). Оправдана только
  обёртка, добавляющая поведение (примеры: валидация, транзакция, маппинг, кэш).
- **R-12** Сигнатура возвращает один результат либо `(результат, error)`; дискретные
  исходы не кодируются ok-флагом (`(T, bool)`) или out-параметром: исход моделируется
  типом результата, валидация - до вызова.
- **R-13** Значения группируются по типу: объявление `type X` - со своим блоком констант
  значений этого типа; значения разных типов в одном блоке не смешиваем.
- **R-14** Больше ~4 аргументов функции (включая контекст) - группировать в
  params-структуру.
- **R-15** Тест проверяет поведение/семантику - наблюдаемое следствие вызова; кейс без
  логики ("конструктор не проставил поле", тривиальные поля структуры, пересказ
  реализации) - не пишем. Новая или изменённая нетривиальная логика (ветвления, парсинг,
  расчёты, доступ, запись данных) проверяется тестами, включая существенные границы и
  сценарии отказа. Существующих тестов достаточно, если они проверяют изменённое
  поведение. Исправление бага сопровождается регрессионным тестом, падающим без
  исправления.
- **R-16** Имя однозначно отражает назначение в контексте системы: контекст допускает
  несколько толкований (валюта, единица, направление) - уточнение в имени.

## Workflow

Гейты: self-check диффа (комментарии - R-2, мёртвый код - R-3, README при коде - R-10) ->
форматтер/линтер/тесты (R-9) -> сдача.
