# Паттерн "ревью диффа": параллельное ревью ветки

Оркестратор - синтезатор вердиктов, код не правит; правки - отдельным циклом по паттерну
"фича". Инварианты - реестр скилла; здесь - маршрут.

## Вход

Необязательные аргументы: base-ветка и/или каноны (через запятую). Аргумент, резолвящийся
в git-ветку, - base; имена скиллов - каноны. Base пуст -> определи сам: upstream текущей
ветки, нет upstream -> `origin/main`.

## Фаза 0 - скоуп ревью

1. Чистота дерева и диапазон диффа `<base>...HEAD` - по скиллу `git-workflow`. Дифф пуст -
   стоп, к человеку.
2. Изменённые файлы: `git diff --name-only <base>...HEAD`.
3. **Домены ревью:** по одному `reviewer` на каждый затронутый канон-домен диффа.
   Разрешение канонов - R-12 (по файлам диффа): golang-прод-код -> `go-service-standards`,
   `tests/functional/` -> `go-integrations-tests`, `.gitlab-ci/`/helm -> канон деплоя
   (репо ci-cd), файлы харнеса -> `harness-authoring`. Есть прод-код/инфра -> добавь
   `adversarial-reviewer`.
4. Отчитайся: base, +N файлов, домены -> каноны, состав ревьюеров.

## Фаза 1 - параллельное ревью

Запусти ревьюеров параллельно (read-only), каждому - диапазон диффа + список файлов его
домена:

- `reviewer` (скилл канона домена) - соответствие канону (per-rule вердикт) - по одному на
  домен;
- `adversarial-reviewer` - попытка сломать изменение (сценарии отказа), без канона - на
  прод-код/инфру.

В таске канонному ревьюеру: per-rule вердикт; гейт-проверяемые и канон текстом - R-13.

## Фаза 2 - синтез

Смержь замечания всех ревьюеров в один список без дублей, с приоритетами:

- **блокер** - ломает корректность/канон, требует правки;
- **фикс** - конкретная безопасная правка;
- **опционально** - полировка на усмотрение;
- **отложить** - с причиной (scope, легаси-контекст).

## Отчёт

Base и размер диффа, вердикт каждого ревьюера, мерж-список по приоритетам, расхождения
ревьюеров по одному факту (если есть) - явными пунктами.
