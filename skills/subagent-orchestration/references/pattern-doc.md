# Паттерн "доменный документ": написание и ревью по канону вида

Артефакты фичи - связанные `doc.md` и `plan.md`, а `tests.md` - существующее покрытие,
если оно есть. Каждый вид проверяется по своему reference скилла doc-canons; product и
postmortem остаются отдельными видами. Инварианты - реестр скилла; здесь - маршрут.

## Вход

Тема, контекст, папка или путь к одному артефакту; если дан путь, сначала прочитай его.
Тип результата и reference определяет команда документа. Для фичи `write-feature-plan`
может начать с темы или заметок: отсутствие выходных `doc.md` и `plan.md` на входе
нормально. Существующие артефакты фичи прочитай; пару `doc.md` и `plan.md` проверяй после
воркера. `tests.md` учитывай только если он уже есть: его выпускает `write-feature-plan`
по финальной спеке. Product и postmortem не требуют комплекта артефактов фичи. Уточнение
требований спеки - до воркера: раунды вопросов ведёт оркестратор (скилл
spec-clarification), документ пишет воркер по готовым решениям. Интервью до документа
закрывает развилки; изложение подтверждается прогоном по готовому документу - одно другое
не заменяет.

## Разметка

- Канон-ревью: reviewer с пином doc-canons применяет реестр запрошенного вида; для фичи
  после воркера проверяет каждый существующий reference и согласованность пары; первый
  прогон - fresh, fix-раунды - resume (R-1/R-2).
- Adversarial замысла - на L (R-9), включая стыки артефактов; S/M-правка секции, кейсы
  малой фичи - без него.

## Цикл

1. **Воркер** пишет или обновляет запрошенный артефакт по команде документа и канону вида.
   Для фичи `write-feature-plan` выдаёт связанную пару `doc.md` и `plan.md`; кейсы
   (`tests.md`) - та же команда по финальной спеке. Гейты команды обязательны.
2. **Прогон по блокам (фича):** после черновика `doc.md` оркестратор прогоняет через
   человека содержательные блоки логики - по одному блоку в сообщении, следующий после
   ответа. Блок самодостаточен для читателя, не открывавшего док: поведение по шагам (вход
   -> исход), термины дока расшифрованы; подача - по канону show-me (поток - псевдокод или
   call-tree, матрица - таблицей, изменение - diff-шeйпом), текст вокруг - prose-style.
   Подтверждение по каждому блоку отдельно ("так" или правка); "так?" на пачку блоков не
   считается. Развилки в прогон не смешиваются: изложение - здесь, открытое решение -
   отдельным вопросом-развилкой. Расхождение - правка блока и повтор только изменённого.
   Блоки подтверждены - `doc.md` финализируется; на L прогон идёт до кейсов (`tests.md`
   выводятся из подтверждённого).
3. **Канон-ревью:** per-rule вердикт по реестру каждого вида и отдельная проверка
   согласованности артефактов. CHANGES_REQUESTED -> fix-задача воркеру (resume) -> повтор;
   cap - R-8.
4. **Adversarial замысла** (L): атака замысла и стыков артефактов по R-9.
   CHANGES_REQUESTED -> решения за человеком (вопрос в чат) -> правка воркером -> повтор
   канон-ревью изменённых секций.
5. **Сдача:** main-осмотр; связанные артефакты и список решений из неоднозначных -
   человеку.

## Границы

- Adversarial не принимает продуктовых решений: замечание - сценарий, выбор - человек.
- Стенограмма интервью - не артефакт; правки живут в документе.
