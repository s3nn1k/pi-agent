# Паттерн "доменный документ": написание и ревью по канону вида

Артефакты фичи - связанные `doc.md` и `plan.md`, а `tests.md` - существующее покрытие,
если оно есть. Каждый вид проверяется по своему reference скилла doc-canons; product и
postmortem остаются отдельными видами. Инварианты - реестр скилла; здесь - маршрут.

## Вход

Тема, контекст, папка или путь к одному артефакту; если дан путь, сначала прочитай его.
Тип результата и reference определяет команда документа. Для фичи `write-research` может
начать с темы или заметок: отсутствие выходных `doc.md` и `plan.md` на входе нормально.
Существующие артефакты фичи прочитай; пару `doc.md` и `plan.md` проверяй после воркера.
`tests.md` учитывай только если он уже есть: его создаёт отдельная команда. Product и
postmortem не требуют комплекта артефактов фичи. Уточнение требований спеки - до воркера:
раунды вопросов ведёт оркестратор (скилл spec-clarification), документ пишет воркер по
готовым решениям.

## Разметка

- Канон-ревью: reviewer fresh с пином doc-canons применяет реестр запрошенного вида; для
  фичи после воркера проверяет каждый существующий reference и согласованность пары;
  fix-раунды - resume (R-2).
- Adversarial замысла - по нетривиальности проработки (R-9), включая стыки артефактов;
  малая правка секции/кейсы малой фичи - без него.

## Цикл

1. **Воркер** пишет или обновляет запрошенный артефакт по команде документа и канону вида.
   Для фичи `write-research` выдаёт связанную пару `doc.md` и `plan.md`; `tests.md`
   выпускает отдельная команда. Гейты команды обязательны.
2. **Канон-ревью:** per-rule вердикт по реестру каждого вида и отдельная проверка
   согласованности артефактов. CHANGES_REQUESTED -> fix-задача воркеру (resume) -> повтор;
   cap - R-8.
3. **Adversarial замысла** (нетривиальные): атака замысла и стыков артефактов по R-9.
   CHANGES_REQUESTED -> решения за человеком (вопрос в чат) -> правка воркером -> повтор
   канон-ревью изменённых секций.
4. **Сдача:** main-осмотр; связанные артефакты и список решений из неоднозначных -
   человеку.

## Границы

- Adversarial не принимает продуктовых решений: замечание - сценарий, выбор - человек.
- Стенограмма интервью - не артефакт; правки живут в документе.
