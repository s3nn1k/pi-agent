# Паттерн "доменный документ": написание и ревью по канону вида

Артефакт - доменный документ по канону вида (спека, тест-кейсы, postmortem; каталог
видов - скилл doc-canons). Инварианты - реестр скилла; здесь - маршрут.

## Вход

Тема/черновик/путь - как в команде документа (write-research / write-test-cases).
Уточнение требований спеки - до воркера: раунды вопросов ведёт оркестратор (скилл
spec-clarification), документ пишет воркер по готовым решениям.

## Разметка

- Канон-ревью: reviewer fresh с пином doc-canons (реестр вида); fix-раунды - resume (R-2).
- Adversarial замысла - по нетривиальности проработки (R-9): риск-домен, новые контракты,
  инварианты денег/данных - да; малая правка секции/кейсы малой фичи - без него.

## Цикл

1. **Воркер** пишет документ по команде документа + канону вида; гейты команды
   обязательны.
2. **Канон-ревью:** per-rule вердикт по реестру вида. CHANGES_REQUESTED -> fix-задача
   воркеру (resume) -> повтор; cap - R-8.
3. **Adversarial замысла** (нетривиальные): атака спеки - сценарии отказа на её правилах,
   границы/пустые значения, гонки, данные/деньги, доступ, противоречия разделов,
   неполнота. CHANGES_REQUESTED -> решения за человеком (вопрос в чат) -> правка воркером
   -> повтор канон-ревью изменённых секций.
4. **Сдача:** main-осмотр; документ + список решений из неоднозначных - человеку.

## Границы

- Adversarial не принимает продуктовых решений: замечание - сценарий, выбор - человек.
- Стенограмма интервью - не артефакт; правки живут в документе.
