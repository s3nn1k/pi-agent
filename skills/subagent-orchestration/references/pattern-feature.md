# Паттерн "фича": полный цикл по готовой проработке

Оркестратор ведёт цикл, код руками не пишет. Инварианты (контексты, раунды, вердикты,
стопы) - реестр скилла; здесь - маршрут.

## Вход

Папка фичи или путь к одному из `doc.md`, `plan.md`, `tests.md` (если путь - сначала
разреши соседние артефакты); опционально каноны. `doc.md` должна быть готовой спекой,
`plan.md` обязателен. Отсутствие `plan.md` - вопрос человеку, без тихого перепланирования.
Отсутствие `tests.md` допустимо, пустой файл не создавать.

## Каноны фичи (домен -> скилл; объяви списком до первой итерации)

Разрешение канона и передача в таске - R-12/R-13 (routing - по каталогу скиллов сессии,
описания - триггеры; несколько канонов - списком); доменные SKILL.md грузи себе до первой
итерации (R-15). Каноны артефактов сдачи объявляй тем же списком и грузи себе сам
(субагентам не передаются): тело MR - канон стиля поверх гит-канона (шаблон MR репо,
лаконичность); UI-дифф - гит-канон (секция скриншотов); `doc.md`, `plan.md` и существующий
`tests.md` - каноны соответствующих артефактов фичи.

## Разметка - итерации и задачи (до Фазы 0)

Разметка - из согласованного `plan.md`: `doc.md` задаёт требования, существующий
`tests.md` - покрытие; здесь - сверка с репо, не построение плана с нуля. Доставка -
итерациями: каждая - рабочий срез (код среза + его тесты), свой MR; агент не мержит -
человек ревьюит и мержит, следующий срез стартует от обновлённого main. На сервисе не
более одного открытого MR по фиче - без стеков и пачек (конвейер ребейзов и пакетное ревью
дороже скорости); треки по разным репозиториям параллельны, по одному MR в каждом.

1. **Разведка** (нетривиальная фича): scout-фанаут fresh по `doc.md`, `plan.md` и репо -
   зоны правки (точки входа, соседние паттерны, объём), тесты и гейты канона. Результат -
   факты, не решения.
2. **Сверка плана:** разметка - из `plan.md`; дополнить каждую задачу зоной правки
   (разведка) и каноном (routing: домен -> скилл). Рез задачи - R-4: прогноз контекста не
   влезает в окно воркера. Расхождение с репо - правка `plan.md`; `doc.md` менять только
   при изменении требований. Отсутствующий план - стоп к человеку, не тихий replan. Одна
   итерация одной задачей - без разведки, сразу к Фазе 0.
3. **Подтверждение:** итог сверки (зоны, каноны, резы) - человеку до Фазы 0, работа после
   подтверждения.

## Фаза 0 - подготовка репозитория

До любых правок (писатели наследуют cwd - ветка должна быть готова до первой итерации).
Подготовь репо по гит-канону сессии. Любой стоп по канону - к человеку, работу не
начинать. Отчитайся: ветка, base, чистота дерева, отставание от origin/main, результат
сверки.

## Итерации 1..N - срезы плана, каждая своим MR

Итерация стартует после Фазы 0; следующая - после мержа предыдущей в main: свежая ветка от
main, не поверх ветки предыдущей. Задачи - из `plan.md` и разметки; домен = задача, раунды
и стопы - реестр скилла (R-2..R-8). Тесты среза - задача той же итерации, не финальная
фаза цикла.

1. **Реализация:** `worker` со скиллом канона домена (передай релевантные файлы/точки
   входа; канон воркер читает сам). Требуй зелёный gate **по канону домена** - команды
   называет канон, воркер отчитывается ими и статусом; ты команды не хардкодишь.
2. **Fix-цикл:** `reviewer` со скиллом канона домена. В таске: per-rule вердикт
   (гейт-проверяемые и канон текстом - R-13).
   - `CHANGES_REQUESTED` -> мерж замечаний (синтез: блокер - одобрение человека / фикс
     сейчас / опционально / отложить с причиной) в `worker` как fix-задача - со скиллом
     канона, как каждый запуск (R-13); ревью повторно.
   - `APPROVED` -> домен готов; следующий.
3. **Граница домена:** файл вне канона задачи - стоп воркера и эскалация. Дефект другого
   домена, всплывший в итерации (красный тест из-за реализации) - возврат в задачу этого
   домена (правка + её ревью), не правка "под тест" здесь.
4. **Сдача итерации:** все задачи итерации APPROVED - adversarial по диффу итерации (R-9):
   нетривиальный - один `adversarial-reviewer` (сценарии отказа, стыки с предыдущими
   срезами); тривиальный - пропустить. `CHANGES_REQUESTED` -> замечания в `worker`
   домена + повторный `reviewer`; после правок adversarial снова по изменившемуся диффу.
   `APPROVED` - сдача по гит-канону: коммиты, пуш, MR (единственный открытый по фиче в
   этом репо); ссылку на MR - человеку. До пуша прогони чек-лист артефактов (каноны -
   раздел "Каноны фичи"): тело MR по канону стиля и шаблону; UI-дифф - по канону
   git-операций (скриншоты); артефакты фичи связаны и синхронны с решениями итерации.
   Далее - следующая итерация.

## Финал - целостность фичи

Последняя итерация - adversarial по стыкам срезов (то, что per-MR ревью не видит), по R-9:
нетривиальная фича - один `adversarial-reviewer` по совокупному диффу фичи от её
стартового main (попытка сломать фичу целиком: сценарии отказа, кросс-итерационные швы);
малая - без него. `CHANGES_REQUESTED` - правка следующим срезом (worker -> reviewer ->
adversarial по изменившемуся). `APPROVED` - фича готова; мерж - человек.

## Приёмка

Сам осмотри совокупный дифф фичи от её стартового main; подтверди focused-валидацию,
связность артефактов по общему контракту и суммаризуй: разметка (итерации, задачи),
итерации (задачи, раунды, статусы, MR), adversarial-финал (раунды), артефакты сдачи по
чек-листу (тела MR, скриншоты, связанные `doc.md`, `plan.md`, `tests.md` если есть),
отложенное, почему цикл остановился.
